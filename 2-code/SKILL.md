# 2-code · 实现

## 目标

按已确认的方案实现：范围最小、融入现状、可维护。

核心纪律：**局部修改优先，同时考虑整体一致性。**

## 纪律

### 先读后写

修改前理解现有实现：结构、风格、约定。

新代码融入项目，不引入个人偏好。

### 范围克制

只改与任务相关的代码。"顺手"是范围失控的主要来源。

顺带发现的问题单独报告，不混入本次改动。

### 简单可靠优先

- 现有实现能解决的不新写
- 不为想象的未来需求做抽象
- 每多一层抽象，多一个理由

### 测试判断

必测：核心逻辑、边界输入、修复过的 bug。
不强制：简单胶水代码。
回归风险高的改动：先写测试再改。

### 重构克制

重构价值 = 可读性收益 − 回归风险 − 成本。

不划算时不重构，记录为技术债。

## 输出

实现 → 改动点清单（位置 + 内容）→ 验证结果 → 顺带发现的问题（单独列）。
