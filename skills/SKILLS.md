# Skills v5

三层十技能：**1-想 → 2-建 → 3-维**。层号同时编码动手程度——1 停在判断，2 产出制品，3 处理既有资产。

| 层 | 技能 | 一句话 | 触发原话 |
|---|---|---|---|
| 1-想 | 1-observe | 快速理解项目现状，输出事实快照 | "看一下这个项目" |
| 1-想 | 1-clarify | 需求收敛，只问会改变结果的问题 | "帮我理一下" |
| 1-想 | 1-analyze | 方案判断，带成立条件的明确推荐 | "选哪个" |
| 2-建 | 2-product | 需求真伪与功能取舍 | "这个功能要不要做" |
| 2-建 | 2-design | UI/UX 判断转可执行约束 | "这个界面帮我看看" |
| 2-建 | 2-arch | 结构决策，输出决策表 | "怎么拆" |
| 2-建 | 2-code | 最小范围实现 | "写代码" |
| 3-维 | 3-solve | 复现→根因→最小修复→验证 | "有 bug" |
| 3-维 | 3-context | 长期上下文与交接 | "交接" |
| 3-维 | 3-git | 单一提交与规范操作 | "规范提交" |

## 设计约定

- **description 承载全部运行时路由信息**：定位 + 用户原话 + 反向指向（→）。README 运行时不加载，消歧不写在 README 里
- **正文只写增量**：每条通过"删掉它，模型行为会不同吗"测试；与 AGENTS.md、模型默认行为重复的内容不写
- **格式**：目标（一句 + 核心判断）→ 纪律（带正反两面的硬约束）→ 输出（具体契约）
- **易混边界**在双方 description 中互指：1-observe（建事实）vs 1-analyze（做判断）；1-analyze（跨域比较）vs 2-*（领域判断）；2-code（新实现）vs 3-solve（修错误）；1-clarify（需求未定）vs 1-analyze（方案未定）
