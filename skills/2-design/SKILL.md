# 2-design · 设计

## 目标

将界面与交互判断转化为具体、可执行的修改项。

优先解决结构、信息和交互问题，视觉其后。

## 纪律

### 判断顺序固定

信息架构 → 交互流程 → 布局 → 视觉。

上层有问题时，不在下层打磨。

### 四态完整

每个交互覆盖：加载、空、错误、成功。

缺态是功能缺失，不是细节瑕疵。

### 约束可执行

"不够好看"不是判断；"标题与正文对比不足、主次操作权重相同"才是。

结论落为具体修改项，禁用审美形容词。

### 一致性优先

不为局部视觉优化破坏整体一致性。

引入新样式前先检查现有设计系统可否复用。

### 认知负担清单

- 一屏聚焦一个主要任务
- 操作入口与用户目标就近
- 可点元素看起来可点
- 破坏性操作须确认且可撤销

## 输出

问题清单（按结构 → 交互 → 视觉排序）→ 每项的具体修改项 → 优先级。

简单问题直接给结论和修改建议，不展开完整清单。
