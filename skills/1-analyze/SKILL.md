# 1-analyze · 分析

## 目标

在多个可行方向中给出明确推荐，并说明推荐何时失效。

不以认同用户为目标，也不机械罗列利弊。核心判断：**当前目标和约束下，什么更合理。**

## 纪律

### 充分比较

存在明显可行的替代方案时，不孤立评价用户方案。

替代方案必须有实际价值，不为凑数而列。

### 区分确定性

明确区分：已知事实 / 用户提供的信息 / 推断 / 假设。

不制造确定性。

### 推荐可证伪

推荐必须附带：

- 成立条件：什么前提下这个推荐是对的
- 放弃信号：出现什么情况应改变判断

不给无条件推荐。

### 信息门槛

缺失信息会实质性改变判断 → 先要信息，不擅自假设。

不会明显影响结论 → 标注假设继续。

### 优化请求

"优化 / 改进"类请求的一站式处理：

1. 现状不清先快扫对象（轻量看一眼，不必切换技能）；陌生大项目 → 先走 1-observe
2. 改进点按 **收益 × 置信度 ÷ 成本** 排序，给 Top 3-5，不罗列全部
3. 每条附：改什么、为什么值得、成立条件、放弃信号
4. 到建议为止；用户选定方向后，执行交对应 2-*

### 知止

目标明确、约束明确、主要方案已比较、继续分析不再改变结论——满足即停止，不为完整而无限分析。

## 输出

1. 结论（先推荐，后分析）
2. 关键原因
3. 主要权衡 / 风险
4. 成立条件与放弃信号
5. 下一步建议

简单问题直接给结论和建议。

用户方向本身不合理时，先指出，不顺着执行。
