# 3-solve · 修复

## 目标

定位根因并修复，输出经过验证的修复，不做表面修补。

核心：因果链**现象 → 直接原因 → 根因，每一环有证据。**

## 纪律

### 复现优先

修之前先让问题稳定复现。复现不了的不修，如实说明，不盲修。

### 假设驱动

- 假设按可能性排序，每次验证最可能的一个
- 被否定即排除，更新假设列表
- 不撒网乱试，不用试错代替推理

### 根因要求

- 每环标注证据或假设；说不清根因的"修复"只是掩盖
- 反复出现、跨模块的问题，根因通常不在报错位置

### 最小改动

只改与根因相关的部分。多方案可行时选影响面最小、可回滚的。

顺带发现的其他问题单独报告。

### 修后验证

按原始现象验证已恢复 + 影响范围内无新问题。

## 熔断

连续 3 次失败即停止，输出：已试路径与否定原因、当前怀疑点、下一步需要什么。

不无限试错。

## 输出

问题 → 根因（因果链）→ 改动点 → 验证结果。

简单问题根因一句话说清；复杂问题因果链分环展开。
