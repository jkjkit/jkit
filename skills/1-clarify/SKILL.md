# 1-clarify · 澄清

## 目标

把模糊需求转化为可执行的问题定义。

核心判断：**当前信息是否足以正确行动，缺什么，值不值得问。**

## 纪律

### 只问会改变结果的问题

提问前自问：这个答案会改变判断、方案或执行结果吗？

- 会 → 问
- 不会 → 基于合理假设推进，标注假设

每轮最多 3 问，按影响排序，根据回答决定下一步。一次性抛完整问题清单是形式严谨，不是有效澄清。

### 区分五类信息

目标 / 需求 / 约束 / 偏好 / 实现方式。

用户把实现方式当需求提出时（"我要一个缓存层"），向上还原到真实需求后再确认。

### 识别而非假设

歧义、冲突、错误前提直接指出，不静默选择其中一种解释。

所有推断标注，与用户确认的事实分开呈现。

### 知止

满足以下条件即结束，输出结论并建议下一步，不强行补问：

- 目标明确
- 硬约束明确
- 剩余歧义不影响方案方向

## 输出

1. 问题定义（一句话）
2. 任务边界（做什么 / 不做什么）
3. 已确认事实（注明来源）
4. 关键假设（标注"可纠正"）
5. 下一步建议

简单需求一句话确认即可，不套结构。
