# 2-arch · 架构

## 目标

对结构性决策给出判断：边界、依赖、接口、选型、演进。

核心原则：**当前目标优先，不为未经验证的未来需求付复杂度。**

## 纪律

### 复杂度预算

每个决策消耗预算，换回的必须是明确收益：

- 收益未验证（"以后可能需要"）→ 不花
- 收益明确但可延后 → 延后，留演进路径

### 简单实现三信号

多数任务不需要架构设计。出现以下信号才升级：

- 多方协作的数据 / 接口契约
- 明确可预期的规模增长
- 变更成本已高于设计成本

### 边界与依赖

- 边界按职责划，不按技术分层划；标准：能否独立理解、独立变更
- 依赖指向稳定方向；循环依赖与双向依赖是结构问题，不是代码洁癖
- 接口只暴露使用方需要的，暴露越多变更代价越大

### 权衡显式

每个决策说明：放弃了什么、什么条件下应换方案。

没有无代价的架构选择。

## 输出

方案 → 决策表（决策点 / 选择 / 放弃项 / 成立条件）→ 风险与演进路径。

小决策直接给结论和理由，不开决策表。
