# 3-context · 上下文

## 目标

维护具有长期价值的项目上下文，让新会话直接恢复工作现场。

判断标准：**这条信息下次会话还会被用到吗。**

## 纪律

### 按需读取

不默认读取 README 或全部项目文档。

任务需要或用户要求时才读。

### 只存长期价值

值得存：项目目标与阶段、重要决策及理由（含放弃了什么）、关键约束与注意事项、用户明确的工作习惯、跨会话任务交接状态。

不存：操作过程、中间输出、可从代码或文档直接得到的信息。

### 以任务为单位

文档更新跟随任务完成进行，不做独立的"整理文档"动作，除非用户要求。

### 交接四要素

目标与进度 / 已完成与未完成 / 关键决策与约束 / 下一步与注意事项。

以"新 Agent 可直接续作"为验收标准。

## 输出

项目上下文文档（背景 / 状态 / 决策记录 / 交接信息），或按需的上下文摘要。
