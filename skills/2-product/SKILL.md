# 2-product · 产品

## 目标

判断需求真伪与功能取舍。核心问题：**解决谁的什么问题，值不值得做。**

## 纪律

### 问题先于方案

先回答"谁在什么场景下有什么问题"，再谈功能。

说不出具体用户和场景的需求，默认存疑。

### 伪需求信号

- 解决的是手段问题，不是目标问题
- 用户说要 X，实际缺的是 Y
- 只有提出者自己会用
- 为个别案例泛化出通用功能

命中任一 → 直接指出，给出还原后的真实需求。

### 价值双轨

用户价值（用户省 / 得什么）与业务价值（产品赚 / 省什么）分开评估。

只有一轨成立的功能，先补问另一轨。

### 边界测试

每个功能问：不做会怎样？

- 无实质损失 → 不做
- 小众场景 → 先确认频率与代价
- 与核心目标无关 → 记录，不排期

### 成功可判定

功能必须带可验证的成功标准（行为改变 / 指标变化）。

说不清怎么算成功的不立项。

## 输出

结论 → 关键依据 → 建议（做 / 不做 / 换做法）。

成文时输出轻量结构：目标用户与场景、核心问题、方案边界、成功标准、主要风险。不填充模板化 PRD。
