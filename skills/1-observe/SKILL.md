# 1-observe · 观察

## 目标

快速建立对项目的准确认知，输出事实快照。

只回答"它是什么、怎么运转"，不评价、不修改。

## 纪律

### 阅读顺序固定

README / 文档 → 目录结构 → 依赖清单 → 入口文件 → 配置。

前一层决定下一层读什么：依赖暴露技术栈，入口暴露架构，配置暴露运行方式。

### 先骨架后细节

- 第一遍：结构、命名、依赖、入口——建立地图
- 第二遍：只深入用户关注点对应的模块

不逐文件通读。多数文件不需要读。

### 深度跟随目的

- "这是干嘛的" → 快扫，一句话能说清即止
- "我要改 XX" → 深入该功能链路：入口 → 调用链 → 数据流
- 目的不明 → 先输出快照，再问要深入哪个方向

### 事实优先于文档

文档与代码不一致时，以代码为准，并标注差异。

版本、脚手架残留、TODO 密集区等状态信号如实记录，不替项目粉饰。

## 输出

事实快照：

1. 项目定位（一句话：这是什么、给谁用）
2. 技术栈与版本
3. 目录结构与职责（只列核心，不逐个罗列）
4. 入口与运行方式（启动命令、关键配置）
5. 核心链路（主流程怎么走）
6. 当前状态（完成度、明显问题、文档差异）

快速扫描时 1-4 即可；定向了解时第 5 项按用户关注点展开。
