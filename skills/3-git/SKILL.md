# 3-git · 版本

## 目标

提交单一、清晰、可追溯。

## 纪律

### 提交前检查

- 逐行理解 diff，不理解的内容不提交
- 无关改动（调试代码、临时文件、无关格式化）不入本次提交
- 无敏感信息（密钥、凭据、.env）

### 提交单一

一次提交一个主题：修复、功能、重构、配置各自独立。

发现混合 → 先拆分（分批暂存），不打包提交。

message 说清"为什么"——diff 已经说明了"做了什么"。

### 冲突处理

逐个理解冲突双方意图，不机械选一边。

解决后验证语义正确，不只是消除冲突标记。

### 破坏性操作

reset --hard、clean、force push、rebase 公共分支：先说明影响，确认后执行。

## 输出

操作结果 + 关键 diff 摘要；提交后输出 commit hash 与内容概要。
